### Data Models
The core database structure must align with the architectural dual-state pattern:
- **AvaGlobalState Table**: Stores persistent core traits (trait_name, value, last_updated) [Source: architecture/4-data-models.md#avaglobalstate-table]
- **Primary Key**: `state_id` (PK) 
- **Trait Storage**: `trait_name` (String, Unique: e.g., 'stress', 'energy', 'mood')
- **Value Format**: `value` (String or Integer) to accommodate different data types
- **Tracking**: `last_updated` (DateTime) for state change monitoring
- **Future Integration**: Table designed to support both static backstory attributes and dynamic simulation updates

### API Specifications
The endpoint must follow established FastAPI patterns and prepare for future consciousness generator integration:
- **Endpoint Pattern**: `/api/ava/conversation` POST method [Source: architecture/2-consciousness-generator-implementation.md#b-for-real-time-user-conversation]
- **Request Format**: JSON with user message field
- **Response Format**: Must include both text reply and emotional state indicator for Dynamic Emotional Backdrop support
- **Authentication**: Prepare endpoint structure for future Auth0 integration [Source: architecture/tech-stack.md#authentication--security]
- **Validation**: Use Pydantic models for request/response validation following established patterns
