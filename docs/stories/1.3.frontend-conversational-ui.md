## Acceptance Criteria
1. A new "Conversation Screen" is built using Next.js and `shadcn/ui`.
2. The UI includes a display area for chat history and a voice input mechanism (using the existing Chrome Web Speech API).
3. The UI can successfully call the `/api/ava/conversation` endpoint and **use the frontend text-to-speech service to speak the text response.**
4. The interface includes the "Dynamic Emotional Backdrop" that can change based on a mood received from the API.

### Frontend Architecture Context
The conversation interface must align with established frontend patterns:
- **Framework**: Next.js 15.4.4 with App Router and React 19.1.0 [Source: architecture/tech-stack.md#frontend-stack]
- **UI Components**: Use shadcn/ui components built on Radix UI for accessibility [Source: architecture/tech-stack.md#ui-ux-libraries]
- **Styling**: Tailwind CSS 4.x with utility-first approach [Source: architecture/coding-standards.md#styling]
- **State Management**: Zustand for global state, existing conversation store available [Source: architecture/tech-stack.md#state-management]
- **Animations**: Framer Motion for smooth backdrop transitions [Source: architecture/tech-stack.md#ui-ux-libraries]

### Existing Speech Infrastructure
The project already has established speech components that should be leveraged:
- **Speech Interface**: `SpeechInterface.tsx` provides Chrome Web Speech API integration [Source: existing code analysis]
- **SimpleSpeech Service**: Located in `@/lib/simpleSpeech` for TTS functionality
- **Conversation Store**: `useConversationStore` manages speech states (listening, speaking, transcripts)
- **Configuration**: Speech settings available in `@/lib/config` for timing and behavior

### API Integration Patterns
Must follow established backend communication patterns:
- **Backend Proxy**: Use existing `/api/backend/[...path]/route.ts` for API calls [Source: architecture/source-tree.md#api-communication]
- **Endpoint**: Target `/api/ava/conversation` endpoint (implemented in Story 1.2)
- **Request Format**: JSON with user message field
- **Response Format**: Includes text reply and emotional state for backdrop updates
- **Error Handling**: Follow existing patterns with proper HTTP status codes

### File Structure Requirements
Based on established project organization:
- **Page Location**: `improv-today-frontend/src/app/conversation/page.tsx` [Source: architecture/source-tree.md#frontend-structure]
- **Components**: `improv-today-frontend/src/components/ConversationHistory.tsx`, `EmotionalBackdrop.tsx`
- **Types**: Define TypeScript interfaces in component files following existing patterns
- **Styles**: Use Tailwind classes, leverage existing UI component library in `src/components/ui/`

### Dynamic Emotional Backdrop Specifications
Based on design requirements, backdrop should reflect Ava's emotional state:
- **Mood Mapping**: Warm yellows for happy, deep blues for sad, soft red pulse for angry [Source: prd/user-interface-design-goals.md#overall-ux-vision]

- **Implementation**: Use Framer Motion for smooth transitions between emotional states
- **Integration**: Connect to emotion field from API response format established in Story 1.2
