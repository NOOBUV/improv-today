## Story
**As a** developer,
**I want** to cleanly separate Ava conversation system from Improv-Today practice system and update routing,
**so that** both systems can coexist without interference while establishing Ava as the primary user experience.

## Acceptance Criteria
1. Auth0 login redirects to `/conversation` instead of `/practice` by default
2. Ava conversation components are cleanly separated from Improv-Today practice components

4. No breaking changes to existing Improv-Today functionality
5. Shared components and utilities are properly abstracted for reuse
6. Clean code boundaries established between the two systems

- **Zustand**: State management that can handle multiple system contexts [Source: architecture/tech-stack.md#state-management]

### Component Separation Strategy
**Ava System Components:**
- Conversation interface components
- Emotional backdrop system  
- Ava-specific UI elements
- Conversation history and state management

**Improv-Today System Components:**
- Practice session components
- Performance analysis tools
- Practice-specific functionality
- Original system workflows

**Shared Components:**
- Authentication components and hooks
- Common UI elements (buttons, modals, forms)
- Navigation and layout components
- API client utilities and services

### File Organization Structure
- **Ava System**: `src/app/conversation/` and `src/components/ava/` [Source: architecture/source-tree.md#frontend-structure]
- **Improv-Today System**: `src/app/practice/` and `src/components/practice/` [Source: architecture/source-tree.md#frontend-structure]
- **Shared Components**: `src/components/shared/` and `src/lib/shared/` [Source: architecture/source-tree.md#frontend-structure]
- **Authentication**: `src/app/auth/` remains shared between both systems [Source: architecture/source-tree.md#frontend-structure]

### Routing Architecture
- **Primary Route**: `/conversation` - Ava conversation system (new default)
- **Disabled Route**: `/practice` - Improv-Today practice system (code preserved, route disabled)
- **Auth Routes**: `/auth/*` - Shared authentication flow
- **API Routes**: `/api/backend/[...path]` - Proxy routes for both systems [Source: architecture/source-tree.md#api-communication]

### State Management Strategy
- **Ava State**: Conversation history, emotional state, user session for Ava interactions
- **Practice State**: Session data, performance metrics, practice-specific user data  
- **Shared State**: Authentication status, user profile, global UI state
- **Clear Boundaries**: Prevent state leakage between systems while allowing shared utilities

### Technical Constraints
- **Code Preservation**: Existing Improv-Today functionality code must be preserved but not user-accessible
- **Clean Imports**: Clear dependency boundaries between Ava and practice systems
- **Shared Resources**: Common components and utilities properly abstracted
- **Performance**: No duplication of shared resources or unnecessary bundle bloat
- **Route Disabling**: Practice routes disabled via route guards, not code deletion
