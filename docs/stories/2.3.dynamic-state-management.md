# Story 2.3: Dynamic State Management System

## Status
Done.

## Story
**As a** simulation engine,
**I want** to update Clara's internal state based on event outcomes and differentiate between global and session-specific state,
**so that** her evolving personality affects future decisions while maintaining personalized conversation experiences.

## Acceptance Criteria
1. Clara's global state (mood, stress, energy) is updated based on daily event outcomes.
2. Session-specific conversation state is managed separately per user interaction but the default is global state. Hence when the session starts the global state will be the base and from there user's conversation can affect the state of session. 
3. Global state influences conversation context but doesn't override session personalization.
4. State changes are logged and trackable through time for analysis.
5. The system provides APIs for querying both global and session state.
